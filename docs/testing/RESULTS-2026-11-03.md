# 테스트 실행 결과

2026-11-03, 현재 `develop` 작업 트리에서 실행했다. Java 21과 로컬 Docker의 Testcontainers MySQL 8.4.9를 사용했다. 운영 DB는 사용하지 않았다.

`sshDeploymentTest`도 통과했다. SSH/SCP 대역으로 엄격한 호스트 키 검사, 포트 지정, SHA-256 전달, 업로드 파일 정리, 원격 명령 실패의 전파를 확인했다. 배포 셸 스크립트의 `bash -n`, 워크플로와 테스트 설정의 YAML 파싱, `git diff --check`도 통과했다.

배포 JAR은 `build/libs/backend-0.0.1-SNAPSHOT.jar`다. 같은 날 사용자 요청으로 시드니 운영 EC2에 SSH로 전송해 재시작과 외부 API 검증까지 완료했다. [배포 기록](DEPLOYMENT-2026-11-03.md)에 체크섬과 확인 결과를 남겼다. GitHub 수동 배포 워크플로를 사용하려면 별도로 `production` Environment의 SSH 접속 정보를 설정해야 한다.

## 테스트 중 확인하고 수정한 동작

| 문제 | 수정 | 회귀 테스트 |
| --- | --- | --- |
| SRID 4326의 응급실 JDBC 조회가 위도를 longitude로 반환 | `ST_Longitude`, `ST_Latitude`로 좌표 의미를 명시 | `EmergencyRepositoryIntegrationTest` |
| 활성 9건 중 CSV 4건을 절반 미만으로 판단하지 못함 | 정수 나눗셈 대신 `staged * 2L < active` 비교 | `PlaceCsvImportIntegrationTest` |
| 없는 응급실 상세가 빈 `200` 응답 | 서비스에서 `404` 예외로 처리 | `EmergencyAcceptanceTest.E02` |
| 삭제된 사용자로 발급된 기존 토큰이 필터에서 `500` 발생 | 인증 컨텍스트를 비워 보호된 API에서 `401` 반환 | `AuthAcceptanceTest.A02` |
| 사용자 ID만으로 토큰을 받는 API가 운영에서도 등록됨 | 테스트 토큰 컨트롤러를 `local` 프로필로 한정 | `AuthAcceptanceTest.A03` |
| 응급실 검색 입력에 Bean Validation이 적용되지 않음 | 좌표 범위, 양수 반경, 최대 30km를 검사 | `EmergencyAcceptanceTest.E02` |
| 기본 정보 API가 빈 목록을 반환하면 전체 응급실이 비활성화될 수 있음 | 병합 전에 빈 목록을 거부 | `EmergencyIntegrationTest` |

CSV 병합 중 실패는 컨테이너 DB의 INSERT 트리거로 주입했다. 그 전에 수행한 UPDATE도 롤백됐고, 임시 테이블 정리 후 다음 갱신이 성공했다. 갱신·재등장·비활성화 과정에서 장소 ID와 즐겨찾기 참조가 유지되는 것도 실제 DB로 확인했다.

정책별 시나리오는 [POLICIES.md](POLICIES.md), SSH 배포 설정은 [DEPLOY-SSH.md](../DEPLOY-SSH.md)에 있다. 상세 HTML 보고서는 저장소 루트의 `build/reports/tests/`에 있다.
