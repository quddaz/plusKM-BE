# PR 검사 정리 설계

## 목적

외부 OpenAI API 크레딧에 의존하는 AI 사전 리뷰를 제거하고, 장기 브랜치 통합 PR이 기능 브랜치 규칙 때문에 차단되지 않도록 한다.

## 변경 범위

- AI 리뷰 전용 GitHub Actions 워크플로를 삭제한다.
- AI 리뷰 실행 스크립트와 전용 리뷰 정책을 삭제한다.
- `develop`에서 `main`으로 보내는 통합 PR은 브랜치 이름과 이슈 연결 검사를 생략한다.
- 그 밖의 PR은 `feat/{issue-number}/{name}` 또는 `fix/{issue-number}/{name}` 규칙과 이슈 연결 문구를 계속 검사한다.
- Gradle 테스트는 모든 대상 PR에서 그대로 실행한다.
- PR에 포함된 기존 커밋 메시지를 Conventional Commits 형식으로 재작성한다.

## 커밋 메시지 규칙

- 동작 변경이 아닌 구조 개선은 `refactor`를 사용한다.
- 테스트 코드 정리는 `test`, 문서 변경은 `docs`, 워크플로 변경은 `ci`를 사용한다.
- 기존 커밋의 코드 내용과 순서는 유지하고 제목만 재작성한다.

## 검증

- 저장소에 AI 리뷰 파일 또는 참조가 남지 않았는지 검색한다.
- 셸 조건을 로컬에서 실행해 `develop`은 통과하고 잘못된 기능 브랜치는 실패하는지 확인한다.
- 전체 Gradle 테스트를 실행한다.

## 제외 범위

- API 크레딧 충전이나 새로운 AI 리뷰 공급자 도입은 하지 않는다.
- 사용자가 작성 중인 `docs/변경점.md`는 수정하거나 커밋하지 않는다.
